# Luna 演进路线图

## 当前定位

Luna 目前是一个研究型语言原型，正从功能验证阶段进入工程化的 Alpha 阶段。

它已经具备 package/module 与显式导出、线性所有权与借用、FFI、Metadata 与
selector、`const` / `constexpr`、初版反射、interceptor / context / slot，
以及 CPU 模拟器、CUDA PTX 与经 ROCm 实机验证的异构计算路径。

当前的首要目标不是继续扩大语言表面，而是冻结核心语义、补齐边界检查、建立回归测试，并使 JIT、AOT 与真实 GPU 后端的行为一致。

## 发布策略

| 阶段 | 目标 | 预计投入 | 发布条件 |
|---|---|---:|---|
| Alpha | 稳定的实验性编译器，可用于内部项目和语言试验 | 约 4 周 | 核心语义冻结、自动回归、明确诊断、Linux JIT/AOT/ROCm 可复现 |
| 封闭 Beta | 允许少量外部开发者试用 | Alpha 后约 4–6 周 | 文档完整、兼容规则清晰、CI 与版本化测试覆盖主要路径 |
| 公开 Beta | 可供更广泛用户尝试 | Alpha 后约 2–3 个月 | 工具链安装稳定、标准库雏形、性能基线、已知限制与迁移策略明确 |

以上时间仅在语言核心语法基本冻结、开发期间不引入新的大型语义系统时成立。

## Alpha 稳定核心

以下能力作为 Alpha 的稳定承诺范围：

- 多文件包、显式 `export` 与包级可见性。
- 基础类型、函数、结构体、枚举、泛型与 trait 的已实现子集。
- 线性类型、`move`、共享/可变借用、引用和取地址。
- FFI 的显式外部声明与链接接口。
- JIT 与 AOT 编译路径。
- `kernel fn`、`device_buffer<i32>`、`launch`、`await` 的初始异构 ABI。
- CPU 模拟器与 ROCm `gfx1101` 路径；CUDA 保持已实现但标记为待硬件验证。
- Metadata 可附加到函数、类型与 trait；静态/动态 selector 和显式运行时保留已实现。

## Alpha 实验性能力

下列能力保留在 Alpha 中，但允许在 Beta 前调整语义或限制范围：

- interceptor / context / slot、`resume()`、`abort()`、`apply` 与显式多发射规则。
- `constexpr`、编译期反射与完整类型信息查询。
- trait 版本组合与复杂泛型约束。
- CUDA 真实设备路径。
- 动态 slot / interceptor/context 调度的优化策略。
- 超出 `device_buffer<i32>` 的通用 GPU 数据模型。

实验性能力必须提供明确诊断、最小示例与已知限制；不得静默产生不安全或未定义行为。

## 四周 Alpha 计划

### 第 1 周：语义冻结与前端可靠性（已完成）

- 为包、导出、版本选择、trait、泛型、FFI 建立规范化测试矩阵。
- 统一类型检查、所有权检查和代码生成之间的边界规则。
- 补足解析恢复、跨文件错误位置、错误码和可操作的 help 信息。
- 为线性变量、借用冲突、未 await event、非法 GPU buffer 重用建立负例回归。

验收：已有有效示例全部通过；每类核心错误都有稳定、可定位、可理解的诊断。

### 第 2 周：JIT、AOT 与基础优化（已完成）

- 确保 JIT 与 AOT 的语言行为、FFI 链接、运行时初始化一致。
- 为 AOT 引入明确的优化级别，并建立基础 LLVM 优化管线：mem2reg、SROA、常量传播、死代码删除和内联策略。
- 补充 AOT 生成物的启动失败诊断，禁止后端初始化失败后静默继续运行。
- 为包编译、链接参数、运行时库发现建立可复现测试。

验收：同一输入在 JIT 和 AOT 下产生一致结果；常见构造不再保留明显可消除的临时栈对象。

完成记录：稳定核心矩阵现对 `-O0`、`-O2`、`-O3` 比较 JIT 与 AOT 的退出码、stdout 与 stderr，覆盖包、FFI、ADT、泛型、版本、trait、反射、闭包和 CPU 模拟器。它还回归了堆形态 ADT 参数默认借用调用方所有权的规则，防止正常调用出现重复释放。

### 第 3 周：异构计算稳定化（已完成）

- 将 ROCm 路径纳入自动化实机冒烟测试；保留 CPU 模拟器作为无 GPU 回归路径。
- 统一 CUDA/ROCm 的 module-load、launch、event、同步与错误传播模型。
- 将 GPU launch 失败变成可观察的程序失败，而不是错误 event 或错误结果。
- 增加批量 host/device 传输 API；避免以大量标量 memcpy 作为正式吞吐接口。
- 建立小型基准：启动开销、传输带宽、简单逐元素 kernel、AOT 与 JIT 首次运行开销。

验收：ROCm 上可重复运行基础 kernel；设备错误有具体后端错误文本；基准结果可复现并记录。

完成记录：launch/event 与批量传输失败会在生成的 host IR 中进入统一的可观测错误边界；CPU 模拟器回归覆盖该 ABI；ROCm JIT/AOT 冒烟测试可通过 `LUNA_ENABLE_ROCM_SMOKE=ON` 启用，且已在配有 RX 7800 XT 的 ROCm 环境中通过。

### 第 4 周：工程化与 Alpha 发布候选（核心已完成，封版待验证）

- 建立 Linux CI：构建、语法/语义负例、JIT、AOT、包、FFI、CPU 模拟器。
- 整理语言参考、安装指南、包指南、FFI 指南、GPU 指南和实验性能力说明。
- 为每个实验性特性列出支持范围、未支持情形和迁移风险。
- 固化 Alpha 版本号、变更日志、示例包和已知问题列表。

验收：全新环境按文档可构建并运行示例；CI 覆盖稳定核心；已知限制可查。

## Beta 前的后续迭代

完整的跨版本路线已整理在 [Alpha 之后的发展路线](future_roadmap.md)，包括异构
计算、动态片段、结构化并发、C FFI、标准库和工具链。

### 类型系统与编译期能力

- 完成 `const` / `constexpr` 的求值模型、缓存、循环限制和诊断。
- 明确反射中“结构化类型”“名义类型”“完整类型描述”的稳定 API。
- 扩展泛型与 trait 的一致性/重叠检查，定义版本选择的冲突规则。

### interceptor / context / slot

- continuation frame、正常恢复、函数返回转移、早退、单发射和动态 `apply` 的第一版语义已落地。
- 静态 context 已使用结构化 CPS CFG；后续仍需把多发射和外部动态插件统一到持久化 frame ABI。
- 增加资源消费与恢复路径的模型检查式测试。

### 异构计算与性能

- 泛化设备缓冲区元素类型、批量复制、二维/三维 grid 与可配置 block。
- 增加 stream、事件依赖、内存池、pinned memory 和 profiling 接口。
- 在 ROCm 与 CUDA 硬件上建立性能基线；对比 AOT/JIT、不同优化级别与传输策略。

### 工具链与生态

- 完善 REPL、格式化工具、语言服务器基础能力与包元数据。
- 建立标准库雏形：字符串、集合、错误处理、并发/异步基础设施。
- 发布 ABI、包版本和弃用策略，提供兼容性测试。

## 性能路线

Alpha 阶段优先保证正确性与可观测性；性能工作按以下顺序进行：

1. 为 AOT 与 JIT 建立可选择的 `-O0`、`-O2`、`-O3` 优化级别。
2. 在宿主 IR 中执行基础 SSA、标量替换、常量折叠、死代码删除和内联。
3. 将设备标量 copy API 补充为批量传输 API。
4. 持续验证静态 interceptor / context / slot 的零额外续延开销。
5. 以真实工作负载评估 GPU launch、传输和 kernel 吞吐，而不是只看单一示例。

## 升级原则

- 每次语义变化必须附带正例、负例和迁移说明。
- 新功能在进入稳定核心前，先以实验性能力发布。
- 安全检查不得为了性能而静默放宽；优化必须保持所有权、借用和 event 生命周期语义。
- 对 CUDA、ROCm、CPU 模拟器保持同一源语言语义；后端差异必须显式记录。
- 优先修复“可能静默产生错误结果”的问题，其次才是增加语法糖。

## 近期下一步

当前 `0.2.0-alpha` 稳定核心已在 Linux、macOS 和 Windows UCRT64 CI 上通过，
默认配置有 26 项非硬件 CTest 回归。语言内部分配/输出已收敛到 Runtime ABI v1，
下一步优先引入一等错误处理，以此支撑标准库和格式化 `std::io`；随后继续收敛
所有权/仿射/线性检查、Moon 容器验证边界和 package 工具链，同时累积
ROCm/CUDA 性能与硬件兼容性记录。原生结构化并发将在这些基础稳定后继续设计。
